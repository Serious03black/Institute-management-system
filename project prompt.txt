
# MASTER PROJECT PROMPT — INSTITUTE MANAGEMENT & EXAM SYSTEM

## 1. Project Overview

Build a complete, production-oriented **Institute Management and Examination System** using Node.js, Express.js, MongoDB Atlas Cloud, and a modern responsive frontend.

The system will be managed through a single Admin account. The Admin must be able to manage students, faculty, courses, modules, batches, examination credentials, online examinations, practical code submissions, results, re-examinations, system settings, and audit logs.

This must be a fully functional web application, not just a UI prototype or static dashboard.

All frontend pages must be connected to working backend APIs and the MongoDB Atlas database. Forms, buttons, filters, search, tables, exam timers, Excel uploads, results, and reports must work correctly.

Before implementation, inspect the project directory and existing code if available. Reuse working components where appropriate, preserve existing functionality, and implement the requirements below systematically.

## 14. Start Exam — Student Examination Interface

Build a dedicated examination interface that is separate from the Admin dashboard.

### 14.1 Exam Login

Display:
- Exam ID input.
- Password input.
- Start/Login button.
- Validation errors.

After successful authentication, display:
- Student name.
- Student ID.
- Course title.
- Assigned modules.
- Completed modules.
- Pending modules.
- Eligibility status.

### 14.2 Module-wise Examination

Each assigned module must have an independent examination.

For each module:
- Allow the student to start the exam.
- Display the module name.
- Create a unique exam attempt.
- Select questions from the corresponding module's question bank.
- Save the exact question set for that attempt.
- Maintain answers and examination status independently.

Once a module exam has been completed, display it as Completed and prevent it from being retaken through the normal exam flow.

A failed module can be made available through the Re-Exam workflow.

### 14.3 Resume Interrupted Exams

If a student closes the browser, refreshes the page, or temporarily loses connectivity:
- Restore the active attempt if it is still valid.
- Restore saved answers.
- Restore the original question order.
- Restore the remaining time using server-side timestamps.
- Do not reset the one-hour timer by refreshing or logging in again.

An active exam must not create a new random question set each time the page reloads.

### 14.4 Examination Security

- Validate exam eligibility on the server.
- Never send correct answers to the student-facing API.
- Calculate objective marks on the server.
- Prevent duplicate submissions.
- Enforce the examination deadline on the server.
- Reject unauthorized attempts to access another student's exam.
- Save exam submissions transactionally or with equivalent safeguards.
- Maintain an immutable history of completed attempts.

Do not rely exclusively on frontend JavaScript for examination security or timing.

# 16. Examination Question Selection

For each standard module examination, select exactly 42 questions:

| Section | Number of Questions |
|---|---:|
| Basic | 10 |
| Mid | 10 |
| Advanced | 20 |
| Practical | 2 |
| Total | 42 |

Requirements:
- Select questions randomly from the correct module's question bank.
- Do not repeat any question within the same exam attempt.
- Save the selected question IDs and their order when the attempt begins.
- Use server-side random selection.
- Do not reveal the correct answers to the frontend.
- A new authorized attempt must receive a new eligible random set.
- If a section does not contain enough eligible questions, do not start the examination. Display a useful error to the Admin.

Randomization must be independent for each module.

The exact question distribution is a mandatory requirement for the standard examination. If the question bank does not contain enough unique questions, the system must report the shortage rather than silently changing the number of questions.

## 20.3 All Results

Provide a search field for Student ID.

Display all module results for the selected student.

For each module, show:
- Module name.
- Basic marks.
- Mid marks.
- Advanced marks.
- Practical marks.
- Total marks.
- Maximum possible marks.
- Percentage, where applicable.
- Pass/Fail status.
- Exam date.
- Attempt type.
- Re-Exam marks and status, if applicable.

### Passing Rule

The minimum passing score is 40 marks per module.

- A score of 40 or above means Pass.
- A score below 40 means Fail.

The system must support a configurable scoring scheme and calculate marks consistently.

The total possible score must be defined by the scoring configuration. Do not assume that the total is 100 unless the Admin's configuration or the approved scoring rules specify it.

The practical score must be included before finalizing the module result.

A module result must remain Pending Review until all required evaluation components, including practical evaluation, have been completed.

### Re-Exam Rules
